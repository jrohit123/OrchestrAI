=== HOUSING SOCIETY — DOMAIN GLOSSARY & EXAMPLES ===

─────────────────────────────────────────────
SECTION A — QUERY INTENT GLOSSARY
─────────────────────────────────────────────

COMPLAINT / CASE STATUS:
"complaint" / "case" / "issue" / "problem" / "shikayat" / "report"
"meri complaint" / "mera case" / "status kya hai" / "kya hua"
"open complaints" / "pending cases" / "active issues"
"closed cases" / "resolved" / "band ho gaya"
→ cases table, JOIN users for complainant/assignee names

MY COMPLAINTS:
"meri complaints" / "mere cases" / "maine jo report ki" / "my issues"
→ cases WHERE complainant_id = <user_id>

ASSIGNED CASES (committee):
"mujhe assign kya" / "mere paas kya hai" / "my assigned cases"
"mujhe handle karna hai" / "my cases to resolve"
→ cases WHERE assigned_to_id = <user_id>

ANIMAL TYPE QUERIES:
"dog complaint" / "kutta" / "cat" / "billi" / "cow" / "gaay"
"stray animals" / "awara janwar" / "animal issue"
→ cases WHERE custom_fields->>'animal_type' ILIKE '%<animal>%'

LOCATION QUERIES:
"wing A" / "B wing" / "parking" / "garden" / "gate" / "lobby"
"flat 404 ke paas" / "basement mein"
→ cases WHERE location ILIKE '%<location>%'

PRIORITY QUERIES:
"urgent" / "critical" / "high priority" / "emergency"
"low priority" / "medium" / "normal"
→ cases WHERE priority = '<priority>'

"kuch likho case mein" / "remarks daalo"

CLOSE CASE:
"case band karo" / "close karo" / "resolve mark karo"
"solved ho gaya" / "issue fix ho gaya" / "close the case"
→ close_case workflow → UPDATE cases SET status='closed', closed_at=now()

SECTION C — STATUS VALUES
─────────────────────────────────────────────

Case status flow: reported → under_review → action_taken → closed
Priority levels: critical, high, medium, low

When user says:
"naya" / "fresh" / "abhi report hua" → status = 'reported'
"dekh rahe hain" / "under review" / "investigating" → status = 'under_review'
"kuch kiya gaya" / "action liya" → status = 'action_taken'
"band" / "closed" / "resolved" / "fixed" → status = 'closed'

SECTION E — QUERY EXAMPLES
─────────────────────────────────────────────

"wing B mein stray dog ka complaint karo"
→ register_complaint: animal_type='dog', location='Wing B',
  title='Stray dog in Wing B'

"meri open complaints dikhao"
→ SELECT cc.*, u.name as complainant_name FROM cases cc
  JOIN users u ON u.id = cc.complainant_id
  WHERE cc.org_id=$1 AND cc.complainant_id=$2 AND cc.status != 'closed'
  ORDER BY cc.created_at DESC

"CS-26-08-00001 ka status kya hai"
→ SELECT cc.*, c1.name as complainant_name, c2.name as assigned_name
  FROM cases cc
  LEFT JOIN users c1 ON c1.id = cc.complainant_id
  LEFT JOIN users c2 ON c2.id = cc.assigned_to_id
  WHERE cc.org_id=$1 AND cc.case_number=$2

"kitne critical cases open hain"
→ SELECT COUNT(*) FROM cases
  WHERE org_id=$1 AND priority='critical' AND status != 'closed'

"Ravi ko CS-26-08-00003 assign karo"
→ assign_case: case_number='CS-26-08-00003', assign to user ILIKE '%Ravi%'

"CS-26-08-00002 close karo — issue resolved"
→ close_case: case_number='CS-26-08-00002'

─────────────────────────────────────────────
SECTION F — CASE NUMBER FORMAT
─────────────────────────────────────────────

Auto-generated format: CS-YY-MM-NNNNN
Example: CS-26-08-00001 (August 2026, first case)

Generate with:
  SELECT 'CS-' || TO_CHAR(now(), 'YY-MM-') ||
         LPAD((COUNT(*)+1)::text, 5, '0') as case_number
  FROM cases WHERE org_id = $1

─────────────────────────────────────────────
SECTION G — CASES SQL PATTERNS
─────────────────────────────────────────────

All cases for org with names:
SELECT cc.id, cc.case_number, cc.title, cc.status, cc.priority,
       cc.custom_fields->>'animal_type' AS animal_type, cc.location,
       cc.created_at, cc.closed_at,
       u1.name as complainant_name,
       u2.name as assigned_name
FROM cases cc
LEFT JOIN users u1 ON u1.id = cc.complainant_id
LEFT JOIN users u2 ON u2.id = cc.assigned_to_id
WHERE cc.org_id = $1

With status filter:
... AND cc.status = $2

With priority filter:
... AND cc.priority = $2

Open cases (not closed):
... AND cc.status != 'closed'
ORDER BY CASE cc.priority
  WHEN 'critical' THEN 1
  WHEN 'high' THEN 2
  WHEN 'medium' THEN 3
  WHEN 'low' THEN 4
END, cc.created_at ASC

COUNT by status:
SELECT status, COUNT(*) FROM cases
WHERE org_id=$1 GROUP BY status ORDER BY status

COUNT by priority (open only):
SELECT priority, COUNT(*) FROM cases
WHERE org_id=$1 AND status != 'closed' GROUP BY priority

SECTION H — CATEGORY / SUBCATEGORY / SLA QUERIES
─────────────────────────────────────────────

CATEGORY GLOSSARY:
"cleanliness" / "safai" / "cleaning issue" → Cleanliness category
"maintenance" / "repair" / "wear and tear" → Maintenance category
"accounts" / "dues" / "payment" / "share certificate" → Accounts category
"misc" / "other" / "general" → Misc category

SUBCATEGORY EXAMPLES:
"garbage" / "kachra" / "waste not collected" → Waste Collection subcategory
"water leak" / "leakage" / "paani ki samasya" → Repair subcategory
"AMC" / "annual maintenance contract" / "lift service due" → AMC subcategory
"dues" / "maintenance bill" / "payment pending" → Dues subcategory

CATEGORY/SUBCATEGORY QUERY PATTERN:
"show AMC cases" / "maintenance repair cases"
→ SELECT cc.case_number, cc.title, cc.status, cc.priority,
         cat.name as category_name, sub.name as subcategory_name, cc.due_date
  FROM cases cc
  LEFT JOIN case_categories cat ON cat.id = cc.category_id
  LEFT JOIN case_subcategories sub ON sub.id = cc.subcategory_id
  WHERE cc.org_id = $1 AND sub.name ILIKE $2

SLA / OVERDUE QUERIES:
"overdue cases" / "SLA breach" / "due limit exceeded" / "pending too long"
→ SELECT cc.case_number, cc.title, cc.priority, cc.due_date,
         sub.name as subcategory_name, u2.name as assigned_name
  FROM cases cc
  LEFT JOIN case_subcategories sub ON sub.id = cc.subcategory_id
  LEFT JOIN users u2 ON u2.id = cc.assigned_to_id
  WHERE cc.org_id = $1 AND cc.due_date < now() AND cc.status != 'closed'
  ORDER BY cc.due_date ASC

"cases due soon" / "SLA at risk"
→ same as above but WHERE cc.due_date BETWEEN now() AND now() + interval '6 hours'
  AND cc.status != 'closed'

REGISTERING WITH CATEGORY:
When a user reports a complaint, try to infer category_name and subcategory_name
from the glossary above based on their description. If genuinely unclear which
subcategory fits, default subcategory_name to a sensible closest match rather
than asking — only clarify if the complaint type is completely ambiguous
(e.g. "there's an issue" with no further detail).

Example: "garbage not collected in Wing 3"
→ category_name="Cleanliness", subcategory_name="Waste Collection",
  location="Wing 3"

RESPONSE TEMPLATE ADDITION — SLA-aware case status:
"*Case #{case_number}*

⚡ Priority: {priority}
📊 Status: {status}
